# Автоматическая приёмка Minecraft

Обновлено:2026-11-02. Проверки выполняются Java-модами в самом Minecraft: новые тестовые миры, настоящие формы/снаряды/урон/пакеты/звуковые события и framebuffer PNG. Управление окном не нужно. Клиент завершает работу после COMPLETE или FAIL.

## Запуск

Требуются JDK 21 для Gradle и JDK 8 для игры; подробности в README.md.

```powershell
.\gradlew.bat runClient -Pvalidation -PhudOnly '-PvalidationRunDir=.tools/run-hud'
.\gradlew.bat runClient -Pvalidation -PvisualOnly '-PvalidationRunDir=.tools/run-final'
.\gradlew.bat runClient -Pvalidation -PsoundsOnly '-PvalidationRunDir=.tools/run-sound'
```

Без выбора режима `-Pvalidation` выполняет полный прогон: POV, AI, кулдауны, все 50 форм и новые пассивы. Без `-Pvalidation` тестовые моды вообще не включаются. Обычный устанавливаемый jar собирать `build` без флагов проверки.

Каждый прогон создаёт собственный мир со своим timestamp; существующие пользовательские миры не открываются. `validationRunDir` изолирует настройки/миры. Результаты в `<gameDir>/morph-validation/…/`; у soundsOnly — `<gameDir>/sound-validation/…/`.

`report.txt` содержит START/PASS/CAPTURE и COMPLETE либо FAIL. Успешный Gradle сам по себе не означает успех сценария: нужно проверить COMPLETE и отсутствие FAIL. Снимки сохраняются в screenshots через ScreenShotHelper, без генерации изображения вне игры.

## HUD и звук

hudOnly сохраняет 208 PNG:5 форм, обе руки, готовность/середина кулдауна/последняя секунда;854×480 и 1024×576 с GUI 1/2/3, настоящий GUI 3 при 1280×720; заполненный хотбар, броня, щит и воздух под водой. Проверяются непересечение со штатным хотбаром/offhand/индикатором атаки, границы экрана и скрытие в F 1/инвентаре/наблюдателе/при смерти. В third person значок остаётся полезным и видимым.

Minecraft 1.12.2 ограничивает минимальный размер GUI и уменьшает нечётный масштаб Unicode-шрифта. Поэтому для проверки настоящего масштаба 3 два случая временно переключаются на en_us; исходная RU-локаль затем восстанавливается. Критерий scale 3 не ослабляется.

Дополнительно 9 дневных presentation-кадров:крипер,паук,курица,шалкер, краткие подписи после превращения. Название при пустой руке показывается как ванильное название предмета; широкого постоянного блока нет.

Для 5 представительных действий `KeyBinding.onTick` вызывает настоящий клиентский обработчик и отправку PacketAbilityUse. Сервер применяет действие и синхронизирует кулдаун; клиентский PlaySoundEvent подтверждает доставленный звук. Сопоставления значков/звуков проверяются для всех 50 форм.

soundsOnly считает события, а не наличие названия в таблице: один успех/урон;5 повторов на кулдауне без нового успеха/урона, с одним тихим личным щелчком; отсутствие цели и неуязвимая цель без урона/расхода кулдауна/звука успеха. Проверяется, что звук отказа не рассылается через публичное World.playSound.

## POV и пассивы

visualOnly сохраняет 88 основных+66 дополнительныхPNG:зомби,скелет,корова,волк,паук,курица,крипер,эндермен,железный голем,гаст и обычный игрок; обе руки, покой, фазы удара 0,15/0,35/0,5/0,65, меч и карта. Параметр ванильного замаха фиксируется для сравнимых кадров; это проверка рендера, а не утверждение о физическом нажатии мыши.

До переходов запоминаются реальные cached-model cubeList/childModels; после каждой формы проверяется неизменность. Клиентская форма проверяется независимо после получения по сети. Руку/композицию дополнительно нужно осматривать на PNG: один счётчик кадров качество не подтверждает.

Серверные утверждения проверяют UNDEAD и инверсию мгновенных зелий, яд/регенерацию, паутину, магическое сопротивление ведьмы, лечение и защиту иссушителя, панцирь шалкера с очисткой, косвенную защиту/безопасный уход эндермена. Естественное восстановление на время измерений выключено, здоровье не сбрасывается каждый тик.

## Полная функциональная серия

Без visualOnly/hudOnly/soundsOnly после POV проверяются absolute cooldown при cow→skeleton→cow, death Clone NBT, волк→овца, настоящее бегство скелета, призыв волков против коровы и отсутствие призыва против синтетического EntityPlayer, реальные блоки при mobGriefing=false/true. Затем приобретаются и применяются все 50 форм: предпосылки действия, полный кулдаун, повтор после 3 тиков, реальные снаряды и выдаваемые предметы.

Для перебора 50 кейсов разрешён явный reset текущего таймера как подготовка fixture. Отдельные проверки сохранения кулдауна таймеры не подменяют. Противник стоит вне фактического bbox формы на луче взгляда. Синтетическая EntityPlayer-цель не заменяет проверку двух сетевых клиентов.

## Фактический результат

Текущая проверка прошла:208 HUD-кадров и настоящие key/packet/sound;154 POV-кадра, неизменность моделей и новые пассивы; звуковые отказы. Полный прогон всех 50 форм/AI ранее также завершился COMPLETE. Обычный release 7.3.1 прошёл запуск и штатную остановку отдельного obfuscated dedicated server.

Снимки и report.txt создаются в каталоге соответствующего игрового прогона. Сводная галерея `evidence/review/index.html` и `ACCEPTANCE.md` остаются локальными материалами и не включены в Git. Сетевой PvP двумя клиентами, реальный полный logout/login/смена измерения и сторонние моды остаются отдельными сценариями конкретной сборки.
